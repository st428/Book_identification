# 最终项目说明

项目名称：图书馆书架智能巡检与索书号识别系统

最终主线：官方 OCR 稳定版 + Web/手机端 + 检测框和 crop 规则优化

## 基本流程

1. 用户在 Web/手机端上传一张或多张书架图片。
2. 后端保存上传图片，并根据图片内容生成缓存键。
3. 系统检测红色书标、底部横红带或候选书号区域。
4. 根据检测框生成 crop，必要时对高瘦 crop 旋正后送入 OCR。
5. 官方 PaddleOCR 识别索书号文本。
6. 后处理规则修正常见 OCR 错误，例如 `1247.7` 修正为 `I247.7`、`O/0` 混淆、`/` 后首字符数字误读等。
7. 系统按书架顺序判断绿色、黄色、红色状态，并生成标注图和 crop 诊断页。
8. Web 端展示多图结果、颜色统计、识别顺序和简单调架建议。

## 模式设计

- 普通模式：`max_side=1200`，速度优先，适合日常批量识别。
- 精细模式：`max_side=1600`，开启可疑 crop 重试，用于黄色较多、OCR 失败或 crop 可疑图片。

## 最终策略

- Web 端固定官方 PaddleOCR mobile OCR。
- 不读取 `BOOK_OCR_REC_MODEL_DIR`，避免误接入实验训练模型。
- 当前缓存版本：`web_official_ocr_stable_20260608_v5`。
- 不继续默认训练识别模型，主要优化点已经从“训练 OCR”转为“检测框、crop 和规则后处理”。

## 交付目录

- `mobile_server.py`：Flask Web 服务。
- `shelf_inspector_fast.py`：检测、裁切、OCR、排序判断和诊断页。
- `mobile_web/`：前端页面。
- `data/`：项目随附训练/测试图片。
- `docs/`：最终说明、测试记录、已知限制和策略文档。
- `stage5_mobile_results/`：运行时上传、缓存、结果和最终演示测试输出。

## 结论

最终版已经完成项目主线功能：多图上传、官方 OCR 识别、普通/精细模式、缓存管理、结果展示、诊断页、黄色复核和姿态提示。后续如需继续提升速度，主要方向应是更快硬件、GPU 推理或替换 OCR 推理框架，而不是继续训练当前自定义识别模型。
